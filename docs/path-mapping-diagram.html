三方 Docker 部署 · 路径映射与界面填法

三个容器共享同一个真实目录，只是各自看到的路径名不同 —— 「连接容器」页两个路径字段填的是不同容器的视角。
① 同一个文件夹，三方各挂一次（下图为演示路径，以你的实际挂载为准）
/volume2/
music/
lxserver 挂载 /volume2/music → /server/music
user1/
音乐仓鼠 挂载 /volume2/music → /data/music 下载目录 /data/music/user1
歌单同步/
媒体库（以 Emby 媒体库「LX同步」为例） 挂载 /volume2/music → /media/music 库路径 /media/music/user1/歌单同步
我喜欢的/ 晴天.flac
紫底 = 第 ① 步「LX 下载目录」要填的路径　·　蓝底 = 第 ② 步「媒体库根路径」要填的路径
② 「连接容器」页两步怎么填（两个路径字段差一层「歌单同步」）
1连接 lxserver
服务地址http://lxserver:19527音乐仓鼠能访问到的地址
API key<token>lxserver 后台「账户」里生成
下载用户名user1lxserver 里的下载用户名
LX 下载目录/data/music/user1音乐仓鼠视角；「歌单同步」的父目录
2连接媒体服务器（以 Emby 为例）
服务器地址http://emby:8096音乐仓鼠能访问到的地址
API key…Emby 后台 → 设置 → API 密钥
媒体库根路径/media/music/user1/歌单同步媒体服务器视角；「歌单同步」本身（点「读取媒体库」可自动填）
③ 三个最容易踩的坑
✅ 同一个真实目录，三个容器各挂一次（没挂的容器就是看不到文件）。
✕ 把「LX 下载目录」填成媒体服务器视角的 /media/music/… —— 音乐仓鼠在自己的容器里找不到这个路径，会读写失败。
✕ 两个字段填成同一个目录 —— 它们差一层「歌单同步」：下载目录是它的父目录，媒体库根是它本身。
💡 填完点「配置体检」自动核对路径层级（只读、不造假绿灯）；媒体库那边点「读取媒体库」自动填路径。
💡 本机直接 npm run dev（无容器）时没有视角差异：两个路径都填宿主机实际路径即可。
