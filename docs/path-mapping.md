# 路径映射（速览）

![三方部署：路径映射与界面填法](path-mapping-diagram.png)

> 上图一页看完：一个真实目录三方各挂一次 → 各容器看到的路径 → 「连接容器」页两个路径字段该填哪个视角 → 三个常见坑。
> 图源 `path-mapping-diagram.html`（改文字后浏览器截长图即可重出）。
>
> ⚠️ **改这页前先读第一节**：「两个字段填的不是同一个目录」是这块最容易翻车的地方（2026-09-27 实测踩到）。

三方（lxserver / Emby / SongHamster）共用**同一批音乐文件**，只是各容器看到的名字不同。
选一个宿主机文件夹 **[文件夹1]** 挂给三个容器，它们各自用固定路径访问：

| 容器 | 访问 [文件夹1] 的固定路径 | 用途 |
|------|--------------------------|------|
| LXServer | `/server/music` | 下载音乐放这里 |
| Emby | `/media/music` | 扫描入库 |
| SongHamster | `/data/music` | 整理 / 移动 / 洗版 |

## 一、两个路径字段 —— ⚠️ **它们不是同一个目录**

界面里两个框，**填的视角不同，指的层级也不同**：

| 界面框 | 填**哪个容器**的视角 | 指向**哪一层** |
|--------|---------------------|---------------|
| **LX 下载目录** | **SongHamster** 自己 | 「歌单同步」的**父目录** |
| **Emby 媒体库根** | **Emby** | 「歌单同步」**本身** |

为什么差一层 —— 看代码里的路径换算（`src/core/paths.ts`）：

```
本项目（SongHamster）视角:  <LX 下载目录>/歌单同步/<歌单名>/晴天.flac
                                    ↑ 这一层是代码自己拼的
Emby 视角:                  <Emby 媒体库根>/<歌单名>/晴天.flac
                                    ↑ 所以媒体库根要指到「歌单同步」本身
```

映射时中间那层「歌单同步」会被去掉，所以**两个字段必然差一层**。

## 二、三步配置

**① 同一个 [文件夹1] 挂给三个容器**
```yaml
lxserver:    volumes: ["[文件夹1]:/server/music"]
emby:        volumes: ["[文件夹1]:/media/music"]
songhamster: volumes: ["[文件夹1]:/data/music"]
```

**② Emby 后台新建音乐媒体库**（推荐名"LX歌单同步"）
文件夹选 `/media/music/歌单同步`。
已有的其它音乐媒体库不受影响、无需改动。

**③ SongHamster 界面填两个路径，点"路径自检"**

| 界面框 | 填 |
|--------|-----|
| LX 下载目录 | `/data/music` |
| Emby 媒体库根 | `/media/music/歌单同步`（= ② 中媒体库选的文件夹） |

## 三、⚠️ lxserver 配了「自定义音乐目录」会**多一层**

lxserver 的每个用户可以单独设「自定义音乐目录」（管理端 `/api/users` 里的 `customMusicDir`）。
一旦设了，它下载时就落到**用户子目录**里，而不是 [文件夹1] 根：

```
实际落盘:  [文件夹1]/user1/歌单同步/<歌单名>/x.flac
                          ↑ 多出来的这层 = lxserver 的用户名目录
```

**这时 [文件夹1] 要取到 `user1/` 那一层**，界面里的值就变成：

| 界面框 | 填 |
|--------|-----|
| LX 下载目录 | `/data/music/user1` ← 注意**带用户名那一层** |
| Emby 媒体库根 | `/media/music/user1/歌单同步` |

> 💡 **怎么判断有没有这层**：登录 lxserver 管理端 → 用户管理 → 看该用户的「自定义音乐目录」。
> 或者直接看宿主机目录：如果 [文件夹1] 下是按用户名分的目录（`user1/`、`user2/`…），就得往里进一层。
>
> 💡 **`LX 下载目录` 该指哪一层，有个硬判据**：那一层下面必须**同时**有
> **`歌单同步/`** 和 **`.songhamster-trash/`** —— 这两个目录都是 SongHamster 自己建在下载根下的
> （`src/core/trash.ts:29`）。看到它们在哪一层，那一层就是答案。

## 四、⚠️ 「测试连接」和「路径自检」**都验不出路径填错**

| 检查 | 实际验什么 | 填错了会怎样 |
|------|-----------|-------------|
| **测试连接**（LX） | 只打一次 `GET /api/user/list`，**纯 API 连通性** | ✅ 照样通过 |
| **路径自检**（下载目录那行） | 只验「目录**存在且可写**」（写个 `.write_test` 再删） | ✅ 照样通过 |
| **路径自检**（媒体库那行） | 媒体库匹配（父子双向都认） | ✅ 照样通过 |

**把下载目录填成任意一个存在且可写的目录，两个检查都会报绿** —— 它们不验"这是不是那个目录"。

填错的后果要到**真跑同步**才暴露：

- 报 `源文件不存在: <下载目录>/xxx.flac`，或者
- 在错的层级下**新建一套空的 `歌单同步/`**、把文件搬过去；而 Emby 的库指向正确那层，**永远等不到新文件**

## 五、常见问题

| 现象 | 解决 |
|------|------|
| 测试连接、自检全绿，但同步找不到文件 | 下载目录填到了「歌单同步」的**上一层**（少了 lxserver 的用户名目录）→ 见第三节 |
| 找不到刚下载的文件 | 确认 [文件夹1] 挂给了三个容器 |
| Emby 扫不到新歌单 | ② 中文件夹必须选 `/media/music/歌单同步` |
| 自检报路径不可写 | 填的目录在 SongHamster 容器里不存在 → 检查 `volumes` 挂载点与填的值是否对得上 |
| 出现 `歌单同步/歌单同步/` | 下载目录填成 `…/歌单同步` 了，应填它的**父目录** |
| 冒出一个新的空 `歌单同步/`，Emby 却没新歌 | 下载目录少了一层（同第一条） |
