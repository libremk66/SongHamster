# 路径映射（速览）

![三方部署：路径映射与界面填法](path-mapping-diagram.png)

> 上图一页看完：一个真实目录三方各挂一次 → 各容器看到的路径 → 「连接容器」页两个路径字段该填哪个视角 → 三个常见坑。
> 图源 `path-mapping-diagram.html`（改文字后浏览器截长图即可重出）。
>
> ⚠️ **改这页前先读第一节**：「两个字段填的不是同一个目录」是这块最容易翻车的地方（2026-09-27 实测踩到）。

三方（lxserver / Emby / SongHamster）共用**同一批音乐文件**，只是各容器看到的名字不同。
选一个宿主机文件夹 **[文件夹1]** 挂给三个容器，它们各自用固定路径访问：

| 容器 | 访问 [文件夹1] 的固定路径 | 用途 |
|------|--------------------------|------|
| LXServer | `/server/music` | 下载音乐放这里 |
| Emby | `/media/music` | 扫描入库 |
| SongHamster | `/data/music` | 整理 / 移动 / 洗版 |

## 一、两个路径字段 —— ⚠️ **它们不是同一个目录**

界面里两个框，**填的视角不同，指的层级也不同**：

| 界面框 | 填**哪个容器**的视角 | 指向**哪一层** |
|--------|---------------------|---------------|
| **LX 下载目录** | **SongHamster** 自己 | 「歌单同步」的**父目录** |
| **Emby 媒体库根** | **Emby** | 「歌单同步」**本身** |

为什么差一层 —— 看代码里的路径换算（`src/core/paths.ts`）：

```
本项目（SongHamster）视角:  <LX 下载目录>/歌单同步/<歌单名>/晴天.flac
                                    ↑ 这一层是代码自己拼的
Emby 视角:                  <Emby 媒体库根>/<歌单名>/晴天.flac
                                    ↑ 所以媒体库根要指到「歌单同步」本身
```

映射时中间那层「歌单同步」会被去掉，所以**两个字段必然差一层**。

## 二、三步配置

**① 同一个 [文件夹1] 挂给三个容器**
```yaml
lxserver:    volumes: ["[文件夹1]:/server/music"]
emby:        volumes: ["[文件夹1]:/media/music"]
songhamster: volumes: ["[文件夹1]:/data/music"]
```

**② Emby 后台新建音乐媒体库**（推荐名"LX歌单同步"）
文件夹选 `/media/music/<用户名>/歌单同步`（`<用户名>` = lxserver 里的下载用户名，见第三节）。
已有的其它音乐媒体库不受影响、无需改动。

**③ SongHamster 界面填两个路径**（照前两节仔细填，填完点「配置体检」核对，见第四节）

| 界面框 | 填 |
|--------|-----|
| LX 下载目录 | `/data/music/<用户名>` |
| Emby 媒体库根 | `/media/music/<用户名>/歌单同步`（= ② 中媒体库选的文件夹） |

## 三、⚠️ lxserver 会**按用户名多一层** —— 这层不能漏

lxserver 把下载文件放在**用户子目录**里，不是 [文件夹1] 根：

```
实际落盘:  [文件夹1]/user1/歌单同步/<歌单名>/x.flac
                          ↑ 这层是 lxserver 的用户名目录，默认就有
```

**所以 [文件夹1] 要取到 `user1/` 那一层**，界面里的值就是第二节 ③ 那两行。

> 💡 **怎么确认用户名**：lxserver 管理端 → 用户管理，每个用户还有个「自定义音乐目录」
> （`/api/users` 里的 `customMusicDir`）—— 设了就是 `<根>/<用户名>`，没设通常也是按用户名分目录，
> 名以实际目录为准。**直接看宿主机目录最准**。
>
> 💡 **`LX 下载目录` 该指哪一层，有个硬判据**：那一层下面必须**同时**有
> **`歌单同步/`** 和 **`.songhamster-trash/`** —— 这两个目录都是 SongHamster 自己建在下载根下的
> （`src/core/trash.ts:29`）。看到它们在哪一层，那一层就是答案。
>
> 💡 万一你的 lxserver 确实**没有**这层（文件直接落在 [文件夹1] 根），
> 那就把上面所有 `<用户名>/` 去掉 —— 判据同上。

## 四、用「配置体检」代替盲填（填完必点）

旧版「测试连接」只验 API 连通性、验不出路径问题，现已升级为「**配置体检**」，
用**只读**手段逐项检查、结论分级（✓ / ⚠️ / ✗ / ℹ️）：

- ✓ **API key 有效**（走 `/api/user/auth/verify`，能报出 key 归属哪个用户）
- ✓ **下载用户名格式正常**（含非 ASCII 字符会当场报错——它会让下载请求直接失败）
- ✓ **下载目录存在且含特征**（下面同时有 `歌单同步/` 和 `.songhamster-trash/`）
- ⚠️ **层级错位线索**：自动探测「上一层/下一层才是对的」（多填/少填一层是最常见的坑）
- ✓ **交叉验证**：抽检 lxserver 上的真实文件，在下载目录里能否找到
  （这是「三方挂载指向同一物理目录」的实锤）

> 诚实说明：体检**不造假绿灯**。目录还没跑过同步、lxserver 上还没有文件时，
> 会如实标「尚不能完全确认」，让你跑一次同步再回来复检——而不是给一个虚假的 ✓。
> （历史上那个只验「目录存在且可写」的「路径自检」按钮正因为给虚假安全感被删掉了，
> 新的体检用真实文件交叉验证，不重蹈覆辙。）

**所以这两个字段照上面三节填，填完点一次「配置体检」。**
硬判据仍是第三节那个：`downloadRoot` 指的那层下面必须**同时**有 `歌单同步/` 和 `.songhamster-trash/`。

## 五、常见问题

| 现象 | 解决 |
|------|------|
| 体检报「层级错位」 | 按提示改用「上一层/下一层」（多填/少填一层是最常见的坑）→ 见第三节 |
| 体检报「一个文件都找不到」 | 下载目录不是 lxserver 落盘的那层 → 核对层级与挂载 |
| 找不到刚下载的文件 | 确认 [文件夹1] 挂给了三个容器 |
| Emby 扫不到新歌单 | ② 中文件夹必须选 `/media/music/<用户名>/歌单同步` |
| 体检报「下载目录不存在」 | 填的目录在 SongHamster 容器里不存在 → 检查 `volumes` 挂载点与填的值是否对得上 |
| 出现 `歌单同步/歌单同步/` | 下载目录填成 `…/歌单同步` 了（**多**了一层），应填它的**父目录** |
| 冒出一个新的空 `歌单同步/`，Emby 却没新歌 | 下载目录**少**了一层（同第一条） |

> 详细说明（逐行 compose、概念区分）见 [path-mapping-detailed.md](path-mapping-detailed.md)
